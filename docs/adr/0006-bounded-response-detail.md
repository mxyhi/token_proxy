# 完整响应详情使用有界捕获和分块存储

开启详情时，响应超过 256 KiB 后转为匿名临时文件，内存写缓冲为 64 KiB；正常结束或客户端取消均将文件所有权交给日志任务，刷完缓冲后按 64 KiB 块与日志行一起提交到 SQLite。详情接口与界面按页读取、替换正文，复制内容明确标记当前范围，避免转发、落库、IPC 和渲染阶段重新汇集完整长流。

完整性优先意味着慢磁盘会通过等待写入向转发施加背压。捕获失败不伪造上游失败：继续转发，将捕获错误与已有前缀写入详情；数据库完全不可写时输出发行构建也保留的错误。临时文件使用匿名文件，关闭或进程退出自动释放；不承诺强杀前未提交日志的崩溃恢复。

历史日志继续兼容原 TEXT 格式。返回页面有界，但 SQLite 对旧大 TEXT 的内部读取仍可能加载全文；新大正文使用块表消除此问题。Kiro 与协议转换自身为生成终态、估算用量保留的内容属于协议状态，本决策不承诺所有转换路径总内存恒定。七天详情清理必须同步清理正文块和捕获状态。
