# Codex 账户维护

本次调整参考 CPA v8.0.3（`acdace936fa7df2905500c7f5e0a97d683138dea`）及官方管理面板 `4530da271ba2e89810d4dccebc57f3091afa590a`。目标是分离额度展示、远端查询和凭证维护，避免一个操作重复触发其它网络请求。

## 额度与渠道

- 打开额度面板只读取已保存的快照。手动刷新仅查询目标账户，不会顺带查询其它账户或兑换 OAuth token。
- 取消后台周期额度查询及成功响应后的主动额度查询。因此快照不保证实时，需要时手动刷新。
- 渠道禁用后不参与后台 Codex 凭证维护；凭证失效或过期时，额度查询不会隐式刷新 token。
- 额度阈值仍使用保存的快照。一个窗口的已知重置时间到达后，该窗口不再阻断路由；另一个尚未重置的窗口仍可阻断。没有重置时间的窗口不会根据缓存年龄猜测额度已恢复。
- 没有额度快照时不凭空认定额度耗尽；阈值设为 0 仍表示关闭额度阈值拦截。

## 凭证并发与错误

- 到期前 24 小时进入 OAuth 刷新窗口。后台每轮结束等待 5 秒后检查本地状态，不等于每 5 秒发送兑换请求；xAI 的检查周期不变。
- 同一账户刷新串行执行，取得刷新权后重新读取凭据；收到 401 时比较失败请求实际使用的 token，优先复用其它请求已经刷新的版本。
- 额度查询的回写只更新额度字段，不能把旧凭证、状态或用户设置写回。
- 普通刷新失败退避 5 分钟；标准 OAuth `error: "invalid_grant"` 按 1 分钟指数增长，最长 30 分钟。提前刷新失败时仍可使用尚未过期且未明确失效的 access token。
- 成功后至少等待 30 秒才再次自动刷新，避免新 token 仍处于 24 小时窗口内时连续兑换。可重试的暂时错误单轮最多尝试 3 次，间隔 1 秒、2 秒，整轮受 30 秒超时约束。
- `refresh_token_invalidated`、`refresh_token_reused` 等明确失效错误需要重新登录或导入，不继续重试。
- Agent Identity 仍使用独立的签名和任务绑定机制，不转换成 OAuth 账户。

## 迁移边界

不改变现有账户和渠道标识，不迁移数据库格式，也不自动重新登录账户。历史高额度快照按窗口重置时间解除拦截；无重置时间时，手动刷新可更新快照。

显式重新登录或导入不同的 OAuth access/refresh token 时，解除旧凭证的 Invalid 标记并清除旧刷新冷却，保留自动刷新开关和额度阈值。只更改到期元数据或重复导入相同失效 token 不会解除 Invalid；新凭据仍须接受后续上游鉴权。

旧版本可能把凭证失效保存为 active；状态快照本身不是有效性证明。新版本在遇到明确失效错误后按新规则处理，不会为修正历史状态主动请求真实账户。

凭证撤销、会话结束和官方封禁是不同事实。仅凭 OAuth 错误不能证明账户被封，也不能推导是额度查询、刷新或客户端指纹导致。客户端指纹本轮只审计，不随账户维护调整而更换。
