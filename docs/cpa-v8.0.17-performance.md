# CPA 对比后 P2 性能验收

开详情时，c32 长流峰值 RSS 的两次交替测量中位数从 **353.8 MiB 降至 72.3 MiB**；慢客户端从 **346.3 MiB 降至 70.1 MiB**，两者均约减少 80%。所有正文完整性校验通过。

普通场景完成 P95 基本相当：详情关 95.2 → 94.1 ms，详情开 91.0 → 89.1 ms。**不能据此宣称所有性能指标无回退**：详情开长流压力场景完成 P95 为 11.66 → 12.71 s（+9.0%），吞吐 22.44 → 20.81 MiB/s（-7.2%），CPU 45.73 → 47.63 s（+4.2%）。详情开普通场景首字 P95 为 35.4 → 44.1 ms，慢客户端首字 P95 为 40.0 → 61.9 ms。

这些是两对交替测量的观测值；桌面后台竞争和人造 BPE 压力导致时延波动，详情关闭的慢客户端完成 P95 也上升了 10.4%。目前可确认内存改善与正文完整，无法把所有时延差异归因于 spool，也未达到“所有场景零回退”的证据标准。没有为了获得更好基准值而改动精确 token 计算。

## 本地测量范围

- 对比对象：上一轮转发修复完成、尚未引入详情 spool 的 BEFORE，与本轮有界捕获／分页详情的 AFTER；不是 CPA 与 Token Proxy 的速度比赛。
- macOS arm64，10 核；release 配置，Tokio 4 worker；真实 HTTP socket、公开 runtime 服务入口、SQLite，本地 mock 无供应商。
- 开关详情 × 普通／长流／慢客户端 × 并发 1／8／32，每场景独立服务进程与数据库。每进程预热一次，全矩阵每场景测两轮。
- 普通响应 66,322 B；长流与慢客户端响应 8,462,038 B；SSE 帧内容是连续 16 KiB `x`，间隔 1 ms，末尾含 usage 与 `[DONE]`。慢客户端每读 16 KiB 暂停 3 ms。
- RSS 与 CPU 计入 runtime＋固定缓冲的 mock，不含独立客户端。CPU 秒覆盖初始化、预热、转发、日志落库和停机，不能视作单请求 CPU 成本。
- 首字是客户端读到第一个正文 byte；完成 P95 是每场景的 nearest-rank，样本数为 2／16／64；低并发 P95 不能当生产 SLO。
- 连续长词会触发精确 BPE，CPU 压力明显高于常见短 token 输出；本次不修改精确 token 算法，不把人造吞吐外推为真实供应商生成速度。

## 正确性与复现

- 共 60 个独立场景，1752 次测量请求和 60 次预热，1812 条日志；全部 HTTP 200、完整字节数、终止 `[DONE]`、SQLite 行数和正文总量通过。
- AFTER 完整矩阵与交替复测均逐条对比持久化正文 SHA256，包含 inline 和 chunk 表两种形态，捕获错误为零。初始 BEFORE 全矩阵只校验正文总量；交替 BEFORE 已补同样 SHA256 校验。
- 脚本：`scripts/forwarding-perf.py`；夹具：`crates/token_proxy_runtime/examples/forwarding_perf.rs`。
- 原始 JSONL、每场景 `/usr/bin/time -l`、二进制 SHA256 与命令：`.planning/2026-10-07-cpa-forwarding-performance-audit/perf-results/`。
- 初次全矩阵：`before.jsonl`、`after.jsonl`；交替复测：`paired-before-{1,2}.jsonl`、`paired-after-{1,2}.jsonl`。

```sh
cargo build -p token_proxy_runtime --example forwarding_perf --release --target-dir /tmp/token-proxy-p2-perf-target
python3 scripts/forwarding-perf.py --binary /tmp/token-proxy-p2-after --label after --output .planning/2026-10-07-cpa-forwarding-performance-audit/perf-results
zsh .planning/2026-10-07-cpa-forwarding-performance-audit/perf-paired.sh
```

旧二进制 `/tmp/token-proxy-p2-before` 从独立源码快照构建；新二进制 `/tmp/token-proxy-p2-after` 从工作树构建。临时路径是本机会话工件，长期复现需要保留两份源码或对应补丁；脚本不会自动重建旧版本。

未做真实供应商、TLS、实际安装应用或生产混合请求验收；这不是生产 QPS/P95 承诺。
